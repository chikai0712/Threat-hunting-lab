# 需求與範圍

狀態：架構基準；環境相關數值待確認。

## 目標

建立可逐步落地的 Threat Hunting 平台框架，從網路／資安硬體、作業系統、軟體服務、雲端與容器平台接收 Log，統一資料表示，支援後續搜尋、偵測、調查及人工核准的回應流程。

使用者已確認的方向：先完成架構與文件；來源應能透過環境設定管理 IP，各來源有獨立正規化 API，並能接收設備 PUSH。真實串接與部署在環境確認後執行。

## 功能需求

| ID | 需求 | 本期交付 | 環境確認後的驗收 |
| --- | --- | --- | --- |
| FR-01 | 多來源 Log 接入 | 七類來源與協定矩陣 | 對每個選定型號／版本實測 |
| FR-02 | 環境變數設定來源 | 設定模型、IP／CIDR、預設停用規則 | 載入、變更、衝突與拒收測試 |
| FR-03 | 來源獨立 API | endpoint 與資料契約 | 對應來源回傳共同 schema |
| FR-04 | 設備 PUSH | HTTP／Syslog 接入設計 | 從實際設備到儲存端的完整路徑 |
| FR-05 | 原文保存與正規化 | Raw／Normalized 分離與參照關係 | 可追溯原文、解析狀態與版本 |
| FR-06 | 重送與故障處理 | 去重、緩衝、隔離佇列與重處理語義 | 離線、重啟、重送與容量故障演練 |
| FR-07 | 查詢與 Threat Hunting | 共同欄位及查詢責任 | 用實際資料驗證查詢與可用時間 |
| FR-08 | 偵測、案件、時間線 | 模組契約與整合規劃 | 規則命中後可追溯案件與證據 |
| FR-09 | 回應與 Purple Team | 建議／核准／執行邊界 | 在授權範圍內驗證與清理 |
| FR-10 | AI／MCP 輔助 | 五種角色與工具權限邊界 | 唯讀工具、證據引用與權限檢查 |

## 非功能需求：定義測量方式，數值待盤點

| 項目 | 待確認輸入 | 後續驗收方式 |
| --- | --- | --- |
| 吞吐 | 平均／峰值 EPS、平均／最大事件 bytes | 以峰值與突發流量壓測 |
| 延遲 | 事件接收到可搜尋／產生告警的時限 | 分開測量 ingest lag、index lag、detection lag |
| 保存 | 原文、索引、案件、稽核各自保存天數 | 到期刪除與證據保留例外測試 |
| 可用性 | 維護窗口、RPO／RTO、單站或跨站需求 | 停機恢復、備份還原與故障演練 |
| 存取 | 身分來源、權限角色、網路區域 | 角色與來源拒收／允許測試 |
| 維運 | 責任人、告警管道、升級方式 | 指標、runbook、回復流程驗收 |

## 本期完成定義

架構、來源／API／資料契約、整合矩陣、環境盤點與實作順序形成一套可相互追溯的文件。每個環境相依項目有「待確認」欄位，每個模組能說明輸入、輸出、責任及失敗處理。

## 後續範圍

真實設備設定、廠牌／韌體專用 parser、Kafka／搜尋平台部署、Kubernetes／AWS IaC、正式身分整合、容量調整、外部 DFIR／SOAR 與 AI 工具接線均在環境確認後安排。現有 PoC 只作為設計參考，不以其預設 port、SQLite 或單程序模型替代正式選型。
